# 面评催办与收集 Agent Demo

双击 `index.html`，直接在浏览器打开。无需安装、联网或启动服务。所有样式、逻辑、虚构业务数据和示例参数均在同一文件中；数据与参数集中在文件顶部 `DEMO` 对象内。刷新或「重置演示」会清空操作记录。

## 最短演示路径

- **A 正常提交**：点击「结果＋原因」→ 检查草稿（可修改并重新确认）→「确认提交」→ 等待模拟 EHR 成功回执，看板变为已提交。
- **B 暂缓安排**：点击 B → 选择 A「可承诺提交时间」并保存 →「＋1 小时」查看到期催办。再次点击 B，选择 B「尚不能承诺」，填写等待事项与下次确认时间 → 保存 → 快进查看不同的进度询问。
- **C 逾期与接管**：点击 C →「＋1 小时」→ 右侧对应任务「详情」→「转人工处理」→ 确认。关闭抽屉，发送任意回复，只会留存并通知 HR。快进不会自动催办。需要恢复时，在详情点击「恢复 Agent 并设定时间」，明确设定未来时间。
- **D 无法理解**：点击 D →「无法理解」→「手动填写」→ 选择结果并输入本人原因 → 生成草稿 → 确认提交。
- **E 写回待核实**：点击 E（自动切为结果不明）→「结果＋原因」→「确认提交」→ 保留原业务状态并显示待核实标记 → 顶部「补发成功回执」→ 已提交。

左侧会话可切换六条任务；保密任务仅在 POPO 卡片隐藏候选人代号和岗位。右侧支持部门、状态筛选，点击任务行查看当前草稿、最近回复、安排与事件。窄屏可切换面试官端 / HR 端。

## 模拟边界

- 本版按三轮工具调用规划；实际未调用模型或 function calling。回复仅支持演示中的有限规则，先匹配「不通过」再匹配「通过」，倾向或不确定表达不会生成正式结果。草稿原因只截取本人输入，修改后必须重新确认。
- POPO 消息、HR 通知、EHR 回执均为本地脚本模拟，不连接任何真实服务，无登录、权限验证、数据库或真实发送行为。
- 仅五种业务状态：待填、已触达、暂缓、已提交、逾期。「提交待核实」「人工接管」均为独立标记。「正在写回」是临时提示。
- 统一演示时钟按 UTC+8 显示；SLA、自动催办间隔和次数均为示例参数。暂缓暂停有效等待，时长单独记录。人工接管和提交待核实暂停催办；成功回执才完成提交。
- 人工接管后，「继续等」保留接管标记；必须明确恢复 Agent 并设定时间才能恢复自动跟进。「补发成功回执」属于演示控制，不是 HR 业务动作。
- 所有数据虚构，无外部图片、字体、CDN、分析脚本或网络依赖；概念原型不代表网易、POPO 或 EHR 官方产品。

公开部署：只需将本目录的 `index.html` 和 `README.md` 上传到 GitHub 仓库根目录，再在 Settings → Pages 中选择从 `main` 分支的根目录部署。仓库和网页的实际发布状态以交付消息为准。
